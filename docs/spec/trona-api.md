# trona API Reference

**Library:** `lib/trona/` (Rust, multi-crate, compiled to `libtrona.so`)
**Edition:** Rust 2024
**Syscall ABI:** Single kernel trap — `KERNITE_SYS_INVOKE` (=0). All kernel operations reach the kernel through capability invocation; there are no separate syscall numbers for IPC, time, signals, etc.

This document catalogs the public API surface of the trona library crates. Rust functions are referenced by crate-qualified path (e.g. `trona_kernel::ipc::mp_call_ctx`). The C ABI exported by `libtrona.so` uses the `trona_` prefix on selected symbols; those are noted where they exist.

### Crate Structure

| Crate | Path | Description |
|-------|------|-------------|
| `trona_kernel` | `kernel/` | Syscall wrapper, capability invocations, IPC, types, bindgen uapi |
| `trona_protocol` | `protocol/` | Wire-format IPC label constants for userland servers |
| `trona_server` | `server/` | Server-side helpers: message dispatch, capability table |
| `trona_runtime` | `runtime/` | Owning slot types, CNode wrappers, sysinfo, per-process services |
| `trona_posix` | `posix/` | POSIX compatibility (Rust API; no C ABI from this crate) |
| `trona_loader` | `loader/` | ELF/PE/CPIO loading; runtime dynamic linkers (`ldtrona-elf.so`, `ldtrona-pe.so`) |

Additional components:

- **`kernel32`** (`win32/`) — Win32 `kernel32.dll` PE implementation (C ABI, Rust-backed).
- **`arch/`** — Architecture fork-stub assembly (`x86_64/fork.S`, `aarch64/fork.S`).

ABI constants (`KERNITE_OBJ_*`, `KERNITE_INV_*`, `KERNITE_ERR_*`, `kernite_ipc_buffer`) are generated by bindgen from `kernite/include/uapi/*.h`; the output lands in `trona_kernel::uapi`. Do not hand-edit those constants — edit the headers and regenerate.

## 1. Conventions

### Naming

- **Rust module functions** use snake_case without prefix (e.g. `invoke::tcb_start`, `ipc::mp_call_ctx`).
- **C ABI exports** from `libtrona.so` use the `trona_` prefix; they wrap the Rust functions and are noted where they exist.
- **POSIX wrappers** in `trona_posix` use the `posix_` prefix (e.g. `posix_open`, `posix_fork`).

### Return Types

| Type | Meaning |
|------|---------|
| `TronaResult` | Raw invocation return: `error` (0=success) + `value` (payload) |
| `u64` | Raw error code from `.error`; 0 on success |
| `i32` return | 0 on success, −1 on error (POSIX convention) |
| `i64` return | Byte count on success, −1 on error (read/write) |
| `Cap` (`u64`) | Capability slot index in the thread's CNode |

## 2. Types

### Core Types (`trona_kernel::core_types`)

| Type | Repr | Description |
|------|------|-------------|
| `Cap` | `u64` | Capability slot index (type alias) |
| `CapRef` | `#[repr(C)]` | `{ addr: Cap, depth: u8 }` — non-owning borrowed reference into a CSpace |
| `LeakedCapRef` | `#[repr(transparent)]` | Wraps `CapRef`; semantically process-lifetime, never released |
| `TronaResult` | `#[repr(C)]` | `{ error: u64, value: u64 }` — raw invocation return |
| `TronaMsg` | `#[repr(C)]` | `{ label: u64, length: u64, regs: [u64; 32] }` — IPC message staging shape |
| `IpcContext` | `#[repr(C)]` | `{ ipc_buffer: *mut uapi::kernite_ipc_buffer, send_cap_count: i32 }` — per-thread IPC state |

`CapRef::flat(addr)` constructs a single-level reference; `CapRef::at_depth(addr, depth)` names a slot via a multi-level CSpace walk. `CapRef::NULL` is the zero value; `CapRef::is_null()` tests it.

Owning handle types (`OwnedSlot`, `OwnedCap`) live in `trona_runtime::core::slot_alloc` and `trona_runtime::core::cnode`.

### IPC Buffer (`trona_kernel::uapi::kernite_ipc_buffer`)

Bindgen-generated `#[repr(C)]` struct occupying exactly 4096 bytes (one page), mapped into every thread's address space at a spawner-configured address. Key fields:

| Field | Type | Description |
|-------|------|-------------|
| `msg[0]` | `u64` | Message info word (label + length + extra_caps encoding) |
| `msg[1..=32]` | `u64` | Inline message registers (up to 32 payload words) |
| `badge` | `u64` | Sender badge word written by the kernel on receive |
| `mp_flags` | `u64` | MessagePipe control flags (reply marker, close, etc.) |
| `mp_txid` | `u64` | `MP_CALL` transaction ID for reply correlation |
| `caps[4]` | `u64` | Send-side: staged caps to transfer. Recv-side: received cap slots |
| `receive_cnode` | `u64` | CNode slot for incoming cap delivery |
| `receive_index` | `u64` | Slot index within receive_cnode |
| `receive_depth` | `u64` | CNode walk depth for receive slot |
| `timeout_ns` | `u64` | Per-operation timeout (`0`=non-blocking, `u64::MAX`=block forever) |
| `reserved[…]` | `u64` | Extended payload words |

### Startup Descriptor Types (`trona_kernel::core_types`)

The kernel communicates process capabilities through an auxv entry rather than fixed cap slots.

| Constant | Value | Description |
|----------|-------|-------------|
| `AT_SALTYOS_STARTUP` | `0x2005` | Auxv tag; value is a pointer to `SaltyOSStartupLayoutV1` |

```rust
#[repr(C)]
pub struct SaltyOSStartupLayoutV1 {
    pub magic: u32,        // b"SLT1"
    pub version: u32,      // 1
    pub cap_table_ptr: u64, // → SaltyOSCapTableV1
    // …additional fields
}

#[repr(C)]
pub struct SaltyOSCapTableV1 {
    pub entry_count: u32,
    pub entries: [SaltyOSCapEntryV1; 0], // flexible array
}

#[repr(C)]
pub struct SaltyOSCapEntryV1 {
    pub role_id: u32,  // SALTYOS_CAP_ROLE_* constant
    pub slot:    u32,  // CNode slot index where the cap was installed
    pub rights:  u32,  // rights mask
    pub flags:   u32,  // entry flags
}
```

The startup descriptor is walked by `rtld` and the CRT at process startup to populate the per-process capability table. Servers and drivers look up their capabilities via `trona_runtime::caps::*` getters (role-based) rather than hard-coded slot indices.

## 3. Well-Known Capability Slots

Only three capability slots are ABI-fixed in every thread's CSpace:

| Constant | Slot | Object Type | Description |
|----------|------|-------------|-------------|
| `KERNITE_CAP_SELF_TCB` | 0 | TCB | Thread's own TCB |
| `KERNITE_CAP_SELF_VSPACE` | 1 | VSpace | Thread's page table root |
| `KERNITE_CAP_SELF_CSPACE` | 2 | CNode | Thread's CNode root |

All other capabilities — service endpoints, hardware caps, untyped memory ranges, IRQ handlers — are delivered via the `AT_SALTYOS_STARTUP` descriptor and placed at spawner-chosen slot indices. Callers retrieve them by role ID through `trona_runtime::caps::*` getters, not by hard-coded slot numbers.

`TCB_YIELD`, `TCB_EXIT_SELF`, and `VSPACE_FUTEX_*` labels invoke against `KERNITE_CAP_SELF_TCB` and `KERNITE_CAP_SELF_VSPACE` respectively; those are the only well-known invocation targets. Everything else requires the spawner to hand the cap in.

## 4. Syscall Wrapper (`trona_kernel::syscall`)

The kernel exposes a single trap. Every kernel operation reaches the kernel through `KERNITE_SYS_INVOKE` (=0).

### `invoke`

```rust
pub fn invoke(cap_ptr: u64, invoke_label: u64, a2: u64, a3: u64, a4: u64, a5: u64) -> TronaResult
```

Raw kernite trap wrapper. Executes `KERNITE_SYS_INVOKE` against `cap_ptr` with `invoke_label`, passing up to four additional argument words. Returns `TronaResult { error, value }`.

**x86_64 register ABI:**

| Register | Direction | Purpose |
|----------|-----------|---------|
| `rax` | in/out | `KERNITE_SYS_INVOKE` in; error code out |
| `rdi` | in | `cap_ptr` |
| `rsi` | in | `invoke_label` |
| `rdx` | in/out | `a2` in; return value out |
| `r10` | in | `a3` |
| `r8` | in | `a4` |
| `r9` | in | `a5` |
| `rcx`, `r11` | clobbered | Kernel overwrites with return RIP / saved RFLAGS |

**AArch64 register ABI:**

| Register | Direction | Purpose |
|----------|-----------|---------|
| `x8` | in | `KERNITE_SYS_INVOKE` |
| `x0` | in/out | `cap_ptr` in; error code out |
| `x1` | in/out | `invoke_label` in; return value out |
| `x2`–`x5` | in | `a2`–`a5` |

### Convenience Wrappers

These are all thin wrappers over `invoke`; they invoke the single `KERNITE_SYS_INVOKE` trap with the appropriate cap and label.

| Function | Cap | Label | Description |
|----------|-----|-------|-------------|
| `futex_wait(addr, expected)` | `KERNITE_CAP_SELF_VSPACE` | `VSPACE_FUTEX_WAIT` | Block while `*addr == expected`; returns error code |
| `futex_wait_timeout(addr, expected, timeout_ns)` | `KERNITE_CAP_SELF_VSPACE` | `VSPACE_FUTEX_WAIT` | As above with nanosecond deadline |
| `futex_wake(addr, count)` | `KERNITE_CAP_SELF_VSPACE` | `VSPACE_FUTEX_WAKE` | Wake up to `count` waiters; returns count woken in `value` |
| `futex_requeue(addr, wake_count, requeue_addr, requeue_count, expected)` | `KERNITE_CAP_SELF_VSPACE` | `VSPACE_FUTEX_REQUEUE` | Wake + requeue (`zx_futex_requeue` shape) |
| `yield_now()` | `KERNITE_CAP_SELF_TCB` | `TCB_YIELD` | Yield current quantum |
| `thread_exit() -> !` | `KERNITE_CAP_SELF_TCB` | `TCB_EXIT_SELF` | Terminate calling thread; does not return |
| `rng_read_bytes(rng_cap, dst, len) -> TronaResult` | `rng_cap` | `RNG_READ` | Fill `dst[..len]` with kernel RNG bytes |
| `system_get_meminfo_raw(sysinfo_cap, out_uaddr)` | `sysinfo_cap` | `SYSINFO_GET_MEMINFO` | Snapshot PMM counters into `*out_uaddr` |
| `system_get_meminfo<T>(sysinfo_cap, out: *mut T)` | `sysinfo_cap` | `SYSINFO_GET_MEMINFO` | Typed form of above |
| `system_shutdown(syscontrol_cap) -> !` | `syscontrol_cap` | `SYSTEM_SHUTDOWN` | ACPI S5 power-off; does not return |
| `clock_read_monotonic(clock_cap)` | `clock_cap` | `CLOCK_READ` | Nanoseconds since boot |
| `clock_read_realtime(clock_cap)` | `clock_cap` | `CLOCK_READ` | Nanoseconds since UNIX epoch |

System caps (`KernelRng`, `Clock`, `SystemInfo`, `SystemControl`, `KernelDebug`) are not at fixed slots; they arrive via the startup descriptor. Callers retrieve them through `trona_runtime::caps::*` and thread them explicitly into these functions.

## 5. IPC Operations (`trona_kernel::ipc`)

IPC is built on `MessagePipe`, `DataPipe`, `EventQueue`, `Watch`, and `Timer` kernel objects. The old Endpoint and Notification object types have been removed.

### Message Info Encoding

```rust
pub fn msginfo(label: u64, length: u64, caps: u64) -> u64
pub fn msginfo_label(info: u64) -> u64
pub fn msginfo_length(info: u64) -> u64
pub fn msginfo_extracaps(info: u64) -> u64
```

Encode/decode a 64-bit message info word:
- bits 6:0 = length (0–32 inline registers)
- bits 11:7 = extra_caps (0–4 capability transfers)
- bits 51:12 = label (operation discriminant)

### IPC Context Management

```rust
pub unsafe fn ipc_context_init(ctx: *mut IpcContext, ipc_buffer_vaddr: *mut kernite_ipc_buffer)
pub unsafe fn clear_send_caps_ctx(ctx: *mut IpcContext)
pub unsafe fn clear_mp_metadata_ctx(ctx: *mut IpcContext)
pub unsafe fn set_send_cap_ctx(ctx: *mut IpcContext, slot_index: i32, cap_slot: u64)
pub unsafe fn set_receive_slot_path_ctx(ctx: *mut IpcContext, cnode: Cap, index: u64, depth: u64)
pub unsafe fn get_receive_slot_path_ctx(ctx: *mut IpcContext) -> (u64, u64, u64)
```

| Function | Description |
|----------|-------------|
| `ipc_context_init` | Initialize IPC context with a mapped IPC buffer page address |
| `clear_send_caps_ctx` | Clear all staged send caps, reset count to 0 |
| `clear_mp_metadata_ctx` | Clear MessagePipe-specific metadata fields (flags, txid) in the buffer |
| `set_send_cap_ctx` | Stage cap `cap_slot` at `slot_index` (0–3) for the next send |
| `set_receive_slot_path_ctx` | Configure receive slot: incoming caps go to `cnode[index]` at `depth` |
| `get_receive_slot_path_ctx` | Read back the configured receive slot path |

### MessagePipe Operations

MessagePipe (OBJ=12) is the core synchronous IPC primitive. A pipe has two sides (Side A and Side B) obtained by retying a MessagePipeCore (OBJ=20) into two MessagePipe caps via `mp_core_pair`. Each side can write records to the other and read records from its own queue.

`MP_CALL` implements synchronous RPC: the caller sends a record with a kernel-assigned `txid`; the server replies by sending a reply-marked record with the same `txid`. The caller blocks until the reply arrives.

Timeout semantics: `timeout_ns = 0` is non-blocking (`KERNITE_ERR_WOULD_BLOCK` if no record ready); `timeout_ns = u64::MAX` (`IPC_TIMEOUT_BLOCK_FOREVER`) blocks indefinitely.

```rust
pub unsafe fn mp_write_ctx(
    ctx: *mut IpcContext, mp: Cap, timeout_ns: u64,
) -> u64

pub unsafe fn mp_read_ctx(
    ctx: *mut IpcContext, mp: Cap, timeout_ns: u64,
) -> u64

pub unsafe fn mp_call_ctx(
    ctx: *mut IpcContext, mp: Cap, timeout_ns: u64,
) -> u64

pub unsafe fn mp_call_with_caps_ctx(
    ctx: *mut IpcContext, mp: Cap, timeout_ns: u64,
) -> u64

pub unsafe fn mp_write_reply_to_ctx(
    ctx: *mut IpcContext, mp: Cap, txid: u64, timeout_ns: u64,
) -> u64

pub unsafe fn mp_write_reply_ctx(
    ctx: *mut IpcContext, mp: Cap, timeout_ns: u64,
) -> u64

pub unsafe fn mp_write_reply_read_ctx(
    ctx: *mut IpcContext, mp: Cap, timeout_ns: u64,
) -> u64
```

| Function | Description |
|----------|-------------|
| `mp_write_ctx` | Write a record to the pipe (server-to-client push, or client send before call). Non-blocking with `timeout_ns=0`. |
| `mp_read_ctx` | Read the next record from the pipe. Blocks until a record is available (subject to `timeout_ns`). |
| `mp_call_ctx` | Send a record and block for the reply (client RPC pattern). The kernel assigns a txid; reply is matched by txid. |
| `mp_call_with_caps_ctx` | `mp_call_ctx` variant that also transfers staged capabilities. |
| `mp_write_reply_to_ctx` | Write a reply to a specific `txid` (explicit txid form). |
| `mp_write_reply_ctx` | Write a reply using the txid the context received from the most recent `mp_read_ctx` call. |
| `mp_write_reply_read_ctx` | Write a reply then immediately read the next record (server main-loop pattern: reply + wait). |

All functions return a `KERNITE_ERR_*` code (0 on success).

## 6. Capability Invocations (`trona_kernel::invoke`)

All kernel operations are capability invocations dispatched on `(cap.obj_type, invoke_label)`. Invoke labels are defined in `kernite/include/uapi/invoke.h` and re-exported through `trona_kernel::uapi`. Labels are assigned in 0x020-stride hex blocks, one block per object type.

### EventQueue Operations (`KERNITE_INV_EQ_*`, labels 0x120–0x127)

| Rust Function | Parameters | Returns | Description |
|---------------|------------|---------|-------------|

EventQueue (OBJ=10, 8336 bytes) is a bounded record ring. Producers (IRQ handler, Watch, Timer) append records; `eq_wait` dequeues the next record or blocks. Records are 64-bit words whose meaning is defined by the producer type.

### Watch Operations (`KERNITE_INV_WATCH_*`, labels 0x140–0x147)

| Rust Function | Parameters | Returns | Description |
|---------------|------------|---------|-------------|
| `watch_register` | `watch, target, state_mask, eq, cookie` | `u64` | Register a Watch against `target`; fires into `eq` with `cookie` when `state_mask` bits change |
| `watch_cancel` | `watch` | `u64` | Disarm the Watch (pending event is not delivered) |

Watch (OBJ=11, 112 bytes) is a lost-wakeup-free state-change detector. `target` must be a watchable object cap (MessagePipe, DataPipe, EventQueue, or other observable). `state_mask` selects which state bits trigger the event. `cookie` is an opaque 64-bit value delivered with the EventQueue record.

`WATCH_DISARM` (label 0x142) is accessible via direct `invoke` to temporarily disable a registered Watch without cancelling it.

### MessagePipe Core Operations (`KERNITE_INV_MP_CORE_*`, labels 0x260–0x262)

```rust

    core: Cap, side_a_slot: u64, side_b_slot: u64,
) -> u64
```

Splits a MessagePipeCore object into two MessagePipe side caps, placed into `side_a_slot` and `side_b_slot`. After this call the core cap is consumed. The two sides communicate with each other: a write on Side A is read on Side B and vice versa.

### VmHierarchyState Operations

VmHierarchyState (OBJ=25, 312 bytes) is a per-COW-tree serialization lock object. It must be retyed from untyped memory by the thread that owns the COW tree root MO, then passed as the `vhs` argument to `mo_clone`, `mo_clone_range`, `vspace_fork_range`, and `vspace_undo_fork_range`. The kernel acquires the lock during these operations to prevent concurrent COW topology mutations.

Dedicated invocation labels are not exposed; VmHierarchyState caps exist only as arguments to other operations.

## 15. Signals (`trona_posix::signals`)

Signal delivery is implemented as role-addressed `MP_CALL` messages to the init supervisor, which dispatches pending signal records. There is no dedicated notification object for signals.

### Signal Installation

```rust
pub unsafe fn posix_signal(sig: i32, handler: usize) -> usize
```

Install a signal handler for `sig`. `handler` is `SIG_DFL` (0), `SIG_IGN` (1), or a function pointer cast to `usize`. Returns the previous handler or `usize::MAX` (SIG_ERR) on error. Notifies init of the new disposition via `MP_CALL`.

### Signal Checking

```rust
pub unsafe fn posix_sigcheck() -> i32
```

Poll for pending signals and dispatch handlers. For each pending signal:
- **Blocked:** re-queued.
- **SIG_IGN:** silently consumed.
- **SIG_DFL with terminate action:** calls `posix_exit(128 + sig)`.
- **User handler:** saves/restores blocked mask, handles `SA_RESETHAND`, calls handler.

Returns the number of signals dispatched.

## 16. Slot Allocator (`trona_runtime::core::slot_alloc`)

Per-process dynamic CNode slot allocator with chained segments and self-expansion protocol.

### Types

```rust
pub enum SlotResult {
    Ok(Cap),      // Successfully allocated
    WouldBlock,   // Expansion in progress; yield and retry
    Exhausted,    // Permanently failed
}
```

### Functions

| Function | Signature | Description |
|----------|-----------|-------------|
| `slot_alloc_init` | `(base: Cap, count: u64)` | Initialize allocator with the pool from the startup descriptor's `cspace_layout` |
| `slot_alloc_is_initialized` | `() -> bool` | Check if allocator has been initialized |
| `slot_alloc_base` | `() -> Cap` | First segment's base slot |
| `slot_alloc_count` | `() -> u64` | Total pool size across all segments |
| `slot_alloc_remaining` | `() -> u64` | Slots remaining across all segments |
| `enable_self_expand` | `(authority_ep: Cap, owner_id: u64)` | Wire the self-expansion path to an authority MessagePipe (rsrcsrv in production) |
| `reserve_expand_temp_slot` | `(slot: Cap)` | Pin a permanent slot reused as the `cnode_move` scratch during self-expansion |
| `self_expand` | `() -> ExpandProgress` | Allocate one `KERNITE_OBJ_CNODE` via the authority and graft it into the expansion window |
| `install_expand_handler` | `(handler: ExpandHandler)` | Override `slot_alloc()`'s exhaustion path with a custom handler |
| `slot_alloc` | `() -> Option<Cap>` | Allocate one CNode slot (triggers `self_expand` on exhaustion if armed) |
| `slot_alloc_async` | `() -> SlotResult` | Allocate with async expansion protocol |

### CSpace Expansion Protocol

When all segments are exhausted, `slot_alloc()` calls `self_expand()`, which sends `RES_ALLOC_OBJECT(KERNITE_OBJ_CNODE, sub_bits=10)` to the authority MessagePipe installed via `enable_self_expand`, then performs `cnode_set_guard` + `cnode_move` to graft the new sub-CNode into the root expansion window. Up to 64 sub-CNodes can be installed per process (64 × 1024 = 65,536 expanded slots above the initial flat segment).

The per-process expansion temp slot is pinned once via `reserve_expand_temp_slot` and reused for every subsequent self-expand call.

rsrcsrv overrides this path by installing a carve-out handler via `install_expand_handler` to sidestep IPC recursion.
